## Routes and verification

The homepage, notes index, and standalone work/project/note pages are in English. Unknown paths use `404.html`. Existing PDF URLs remain available. Legacy career routes redirect to the corresponding homepage sections, and the previous blog index redirects to the notes index. Consulting/services routes lead to the contact section.

Verify the homepage at desktop, tablet, and phone widths; the mobile menu; the delivery workflow controls; dialog opening/closing and keyboard focus; the standalone content fallback without JavaScript; reduced motion; all PDF downloads; metadata; and nonexistent routes.

`docs/production-snapshot.sha256.json` records SHA-256 checksums for the current public artifact and is refreshed by the generator. It originally described the 56-file S3 snapshot; the English redesign replaces that artifact. Git history retains the migration baseline.

## Domain cutover

The canonical domain is `korvuz.site`. Attach it to the Vercel production environment. Add `www.korvuz.site` separately and configure a permanent redirect to the canonical domain. When adding just `www`, disable the option that also adds apex variants to avoid a redirect to itself.

In Cloudflare, update only the apex and `www` records to Vercel's project-specific values and use DNS-only records. Preserve records for Atlas, other subdomains, mail, and verification services. Wait for valid domain configuration and valid HTTPS on both hostnames.

## Retiring the previous hosting

Do not remove CloudFront while `www` still resolves to it, while HTTPS on Vercel is incomplete, or while old DNS records can still be cached within their previous TTL. Keep a copy of the previous source, Git mirrors, and production files outside the VPS before removing local originals.

Once the new deployment is verified and the cutover has settled, remove only the obsolete website's S3/CloudFront resources and its old Nginx vhost/public files. Check shared resource references before removing policies, functions, certificates, or VPS services. Korvuz Atlas and the backup archive have a separate lifecycle.

If cutover verification fails, restore the saved apex/`www` DNS records while the previous hosting remains available.

Canonical hostname redirects are managed exclusively in Vercel Settings → Domains. Avoid adding an opposite host redirect in `vercel.json`, which would conflict with a dashboard redirect.
