ค่า AWS เดือนละเท่าไหร่ สำหรับเว็บ SME — แจกแจงบิลทีละก้อน และวิธีลดบิลที่ทำได้จริง

คำถามนี้ตอบเป็นตัวเลขเดียวไม่ได้ เพราะ AWS ไม่ได้ขายเป็นแพ็กเกจแบบโฮสติ้ง แต่คิดเงินเป็นรายชิ้นแล้วรวมกันตอนสิ้นเดือน สิ่งที่ช่วยได้มากกว่าคือ รู้ว่าบิลประกอบด้วยอะไรบ้าง เพราะพอรู้แล้วคุณจะเดาบิลตัวเองได้ และรู้ว่าถ้าจะลด ต้องไปลดตรงไหน

หมายเหตุเรื่องตัวเลข: ราคาในบทความนี้เป็นช่วงประมาณการ สำหรับรีเจี้ยน Singapore (ap-southeast-1) ซึ่งคนไทยนิยมใช้เพราะ latency ต่ำ AWS ปรับราคาและออกบริการใหม่ตลอด ก่อนตัดสินใจจริงให้กดคำนวณที่ AWS Pricing Calculator อีกครั้งเสมอ ตัวเลขที่นี่ไว้ใช้ตั้งงบคร่าว ๆ ไม่ใช่ใบเสนอราคา

บิล AWS ประกอบด้วยอะไรบ้าง

เว็บหนึ่งเว็บบน AWS มักมีของ 5 ก้อนนี้ ถ้าเข้าใจ 5 ก้อนนี้ คุณอ่านบิลตัวเองออกแล้ว 90%:

ก้อน คิดเงินยังไง ประมาณการ / เดือน
เครื่อง (EC2) คิดรายวินาที/ชั่วโมง ตราบใดที่เครื่องเปิดอยู่ ถึงไม่มีคนเข้าเว็บก็คิด ฿500–2,500
ดิสก์ (EBS) คิดตามขนาดที่จอง ไม่ใช่ที่ใช้จริง — จอง 100GB ใช้ 10GB ก็จ่ายเต็ม 100 ฿100–400
แบนด์วิดท์ขาออก ขาเข้าฟรี ขาออกคิดตาม GB ที่ส่งให้ผู้ใช้ ฿0–1,500
ฐานข้อมูล (RDS) เหมือนเครื่อง แต่แพงกว่าเพราะรวมงานดูแล/สำรองข้อมูลให้ ฿700–3,000
NAT Gateway คิดทั้งรายชั่วโมง และตามข้อมูลที่วิ่งผ่าน ฿1,200+

สังเกตแถวสุดท้าย — NAT Gateway คือตัวที่สร้างความประหลาดใจในบิลบ่อยที่สุด มันเป็นแค่ทางออกอินเทอร์เน็ตของเครื่องที่อยู่ในเครือข่ายปิด ไม่ได้ให้บริการอะไรกับผู้ใช้เว็บโดยตรง แต่หลายเคสมันแพงกว่าค่าเครื่องเสียอีก และคนส่วนใหญ่ไม่รู้ว่ามันอยู่ในระบบตัวเองด้วยซ้ำ

3 ระดับงบ ที่เจอจริงกับ SME ไทย

ระดับ 1 — เว็บบริษัท / แลนดิงเพจ · ราว ฿500–1,500 ต่อเดือน

เครื่องเล็กเครื่องเดียว ดิสก์ 20–30GB ทราฟฟิกไม่กี่พันคนต่อเดือน ไม่มีฐานข้อมูลแยก ถ้าเว็บคุณเป็น static จริง ๆ ระดับนี้ยังใช้ AWS เกินความจำเป็นด้วยซ้ำ — เอาขึ้น S3 + CloudFront หรือโฮสติ้งธรรมดาก็จบ ถูกกว่าและงานดูแลน้อยกว่ามาก

ระดับ 2 — เว็บที่มีระบบหลังบ้าน · ราว ฿2,500–6,000 ต่อเดือน

มีแอปจริง มีฐานข้อมูล มีระบบสมาชิกหรือคำสั่งซื้อ ระดับนี้เริ่มมีเครื่อง + RDS + ดิสก์ + แบนด์วิดท์ครบก้อน และเป็นจุดที่ควรเริ่มทำ backup อัตโนมัติกับ monitoring ได้แล้ว เพราะระบบเริ่มพังแล้วเจ็บ

ระดับ 3 — ระบบที่ล่มไม่ได้ · ฿10,000 ขึ้นไปต่อเดือน

มี load balancer, เครื่องหลายตัวข้าม availability zone, ฐานข้อมูลแบบสำรองอัตโนมัติ, NAT Gateway ราคากระโดดเพราะคุณเริ่มจ่ายค่า ความไม่ล่ม ไม่ใช่ค่าพลังประมวลผล ถ้าธุรกิจยังไม่ถึงจุดที่ล่ม 2 ชั่วโมงแล้วเสียหายจริงจัง ยังไม่ต้องรีบขึ้นระดับนี้

7 วิธีลดบิล ที่ทำได้จริงในสัปดาห์เดียว

  • 1.ตั้ง Budget alert ก่อนอย่างอื่น — ตั้งวงเงินแล้วให้ AWS อีเมลเตือนเมื่อถึง 50/80/100% ฟรี และช่วยไม่ให้เจอบิลช็อกตอนสิ้นเดือน
  • 2.ลบดิสก์กำพร้า — ปิดเครื่องแล้วแต่ดิสก์ยังอยู่ = ยังจ่ายอยู่ ตรวจ EBS ที่สถานะ available แล้วลบทิ้ง
  • 3.ตั้งอายุ snapshot — ตั้ง lifecycle ให้ลบอัตโนมัติหลัง 7–30 วัน ไม่งั้นมันสะสมไปเรื่อย ๆ เงียบ ๆ
  • 4.เอาไฟล์นิ่งออกจากเครื่อง — รูป วิดีโอ ไฟล์ดาวน์โหลด ย้ายไป S3 แล้วเสิร์ฟผ่าน CloudFront ถูกกว่าและเว็บเร็วขึ้น
  • 5.ทบทวนว่าต้องมี NAT Gateway จริงไหม — หลายระบบขนาดเล็กออกแบบใหม่นิดเดียวก็ไม่ต้องใช้ ประหยัดเดือนละหลักพันทันที
  • 6.ปิดเครื่องทดสอบนอกเวลางาน — เครื่อง dev/staging ที่เปิดทิ้ง 24 ชม. จ่ายเกินจริงเกือบ 3 เท่าของที่ใช้จริง ตั้งเวลาปิด-เปิดได้
  • 7.ค่อยผูก Savings Plan ทีหลัง — ลดได้เยอะจริง แต่ผูกยาว 1–3 ปี ควรทำหลังจากรู้แน่แล้วว่าใช้เท่าไหร่ ไม่ใช่เดือนแรก

คำเตือนเรื่อง Free Tier

Free Tier ใช้ทดลองได้ดีมาก แต่มีสองอย่างที่ต้องรู้: หนึ่ง มันมีเพดานทั้งชั่วโมงเครื่อง ดิสก์ และแบนด์วิดท์ สอง พอเกินเพดาน มันไม่ตัดบริการ แต่เริ่มคิดเงินเงียบ ๆ เคสที่เจอบ่อยคือทดลองไว้แล้วลืม พอผ่านไปหลายเดือนถึงเห็นบิลสะสม ฉะนั้นข้อ 1 ในหัวข้อก่อนหน้า (ตั้ง Budget alert) ควรทำตั้งแต่ชั่วโมงแรกที่เปิดบัญชี

แล้วควรขึ้น AWS ไหม

ตอบตรง ๆ: ถ้าเว็บคุณโหลดนิ่ง ไม่มีช่วงพีค และตอนนี้ยังไม่มีปัญหา — ยังไม่ต้องขึ้นก็ได้ AWS คุ้มตอนที่คุณต้องการความยืดหยุ่นหรือความทนทานที่เครื่องเดียวให้ไม่ได้ ไม่ใช่ตอนที่อยากประหยัด เรื่องนี้กับเช็กลิสต์ก่อนย้าย เขียนละเอียดไว้ที่ ย้ายระบบขึ้น AWS ต้องรู้อะไรบ้าง

และถ้ากำลังชั่งใจว่าจะจ้างใครมาช่วยวางระบบ ลองอ่าน จ้างฟรีแลนซ์ DevOps ต่างกับจ้างบริษัทยังไง ก่อนตัดสินใจ
