เหมาะกับใคร — และไม่เหมาะกับใคร

บอกไว้ตรงนี้เลยเพื่อไม่ให้เสียเวลาทั้งสองฝ่าย

เหมาะ ถ้าคุณ…

  • ·มีระบบอยู่แล้ว แต่ไม่แน่ใจว่าวางถูกทางไหม
  • ·บิลคลาวด์ขึ้นเรื่อย ๆ แต่ไม่รู้ว่าตัวไหนกิน
  • ·มีทีม dev แต่ไม่มีคนดูฝั่ง infrastructure
  • ·กำลังจะย้ายขึ้นคลาวด์ อยากให้มีคนช่วยดูแผนก่อนลงมือ
  • ·ได้ใบเสนอราคาจากเจ้าอื่นมา อยากให้คนกลางช่วยอ่าน

ยังไม่เหมาะ ถ้าคุณ…

  • ·ต้องการคนรับสายตี 3 ทุกคืน — ผมทำงานประจำอยู่ ไม่รับ on-call 24/7
  • ·อยากได้คนมานั่งประจำออฟฟิศเต็มเวลา
  • ·ต้องการทีมหลายคนเข้าทำพร้อมกันในดีดไลน์สั้น
  • ·อยากได้แค่คนกดตามที่สั่ง โดยไม่อยากฟังข้อโต้แย้งทางเทคนิค

เรื่องที่ถูกถามบ่อย

ตัวอย่างโจทย์ที่งานที่ปรึกษาช่วยได้ พร้อมรูปแบบที่มักเหมาะที่สุด

ค่าใช้จ่าย

“บิล AWS เดือนละหลายหมื่น ลดได้ไหม”

ไล่ดูว่าบิลไปกองที่ service ไหน แล้วแยกว่าอันไหนลดได้ทันที อันไหนต้องแก้สถาปัตยกรรมก่อน

เหมาะกับ: ตรวจระบบครึ่งวัน
ก่อนลงมือ

“จะย้ายจาก server เดิมขึ้นคลาวด์ ควรเริ่มยังไง”

วางลำดับการย้าย ประเมินความเสี่ยงและ downtime ตั้งงบคร่าว ๆ ก่อนตัดสินใจจ้างใครทำ

เหมาะกับ: รายชั่วโมง 2–4 ชม.
ความเสี่ยง

“ถ้าเครื่องพังตอนนี้ กู้กลับได้จริงไหม”

ตรวจว่ามี backup อยู่จริงไหม เคยลองกู้หรือยัง และใช้เวลากู้จริงนานแค่ไหน

เหมาะกับ: ตรวจระบบครึ่งวัน
กระบวนการ

“ทีม deploy ด้วยมือ อยากทำ CI/CD ต้องลงทุนแค่ไหน”

ดูของที่มีอยู่ก่อน แล้วเสนอเวอร์ชันที่เล็กที่สุดที่ใช้ได้จริง ไม่ต้องรื้อทั้งระบบ

เหมาะกับ: รายชั่วโมง หรือ retainer
คนกลาง

“ได้ใบเสนอราคาจาก vendor มา ราคาสมเหตุสมผลไหม”

อ่านขอบเขตงานให้ ชี้จุดที่เขียนกว้างเกินไป และคำถามที่ควรถามกลับก่อนเซ็น

เหมาะกับ: รายชั่วโมง 2 ชม.
ต่อเนื่อง

“ระบบขึ้นแล้ว แต่ไม่มีใครดูต่อ”

ตั้ง monitoring และการแจ้งเตือนให้ แล้วดูให้เป็นรอบ ๆ พร้อมรีวิวสิ่งที่เกิดขึ้นแต่ละเดือน

เหมาะกับ: retainer รายเดือน

ขั้นตอนการทำงาน

01

คุยรอบแรก 20 นาที

ฟังปัญหา ประเมินว่าช่วยได้จริงไหม ไม่คิดเงิน ถ้าไม่ตรงกับที่ถนัดจะบอกตรง ๆ

02

ตกลงขอบเขต + ราคา

สรุปเป็นข้อความว่าจะดูอะไร ใช้กี่ชั่วโมง ราคาเท่าไหร่ ก่อนเริ่มทุกครั้ง

03

ลงมือ

คุยออนไลน์ หรือขอสิทธิ์เข้าดูระบบแบบอ่านอย่างเดียวก่อนเสมอ

04

ส่งสรุป

สรุปเป็นเอกสารทุกครั้ง เอาไปให้ทีมอื่นทำต่อได้ ไม่ผูกขาดกับผม

ทำไมถึงเชื่อคำแนะนำนี้ได้

งานประจำคือ Senior DevOps Specialist — ดูแล infrastructure ที่มีคนใช้จริง ทั้ง Kubernetes/Amazon EKS และ Jenkins pipeline ก่อนหน้านี้ทำ AWS migration และ Infrastructure as Code ด้วย Terraform และ Ansible ให้ธนาคารและลูกค้าองค์กร นอกเวลางานสร้างและดูแลโปรดักต์ของตัวเองที่รันอยู่บนเซิร์ฟเวอร์จริง ทุกตัวเปิดให้เข้าไปกดดูได้

ดูโปรดักต์ที่รันอยู่จริง ดูประวัติการทำงาน

คำถามที่พบบ่อย

ปรึกษาครั้งแรกเสียเงินไหม

คุยรอบแรกประมาณ 20 นาทีเพื่อฟังปัญหาและประเมินว่าช่วยได้จริงไหม ไม่คิดเงิน ถ้าประเมินแล้วว่างานไม่ตรงกับที่ถนัดจะบอกตรง ๆ และแนะนำทางอื่นให้ ค่าบริการเริ่มนับเมื่อเริ่มลงมือดูระบบหรือให้คำแนะนำเชิงเทคนิคจริง

เรตที่ปรึกษา DevOps รายชั่วโมงในไทยอยู่ที่เท่าไหร่

เรตที่นี่อยู่ที่ ฿1,500–2,500 ต่อชั่วโมง ขั้นต่ำ 2 ชั่วโมง งานที่เป็นการให้คำแนะนำหรือรีวิวแบบไม่แตะระบบจริงคิด ฿1,500 ส่วนงานที่ต้องเข้าไปดูหรือแก้ระบบที่ใช้งานจริงคิด ฿2,500 เพราะมีความเสี่ยงและต้องเตรียมงานก่อนเข้า

ต่างจากการจ้างทำโปรเจกต์ยังไง

จ้างทำโปรเจกต์คือจ้างให้ส่งมอบชิ้นงานที่ตกลงขอบเขตไว้แล้ว เช่นทำเว็บหรือย้ายระบบขึ้นคลาวด์ คิดเป็นราคาต่อโปรเจกต์ — ดูได้ที่ หน้าแพ็กเกจ ส่วนที่ปรึกษาคือซื้อเวลาและความเห็นทางเทคนิค เหมาะตอนที่ยังไม่รู้ว่าควรทำอะไร หรือมีทีมอยู่แล้วแต่ต้องการคนช่วยตัดสินใจและรีวิว

ตรวจระบบครึ่งวันแล้วได้อะไรกลับไปบ้าง

ได้รายงานเป็นเอกสารที่ระบุสิ่งที่ตรวจพบ จัดลำดับตามความเสี่ยงและผลกระทบ พร้อมข้อเสนอแนะว่าควรแก้อะไรก่อนหลังและแต่ละข้อใช้แรงประมาณเท่าไหร่ และมีนัดรีวิวรายงานอีก 1 ชั่วโมงเพื่อถามต่อได้ รายงานเป็นของคุณ จะเอาไปให้ทีมอื่นทำต่อก็ได้

รับงานเร่งด่วนหรือ on-call 24 ชั่วโมงไหม

ไม่รับ on-call 24 ชั่วโมง เพราะทำงานประจำอยู่ และไม่อยากรับปากในสิ่งที่ทำไม่ได้จริง นัดคุยได้ช่วงเย็นวันทำการและวันหยุด ตอบกลับข้อความภายใน 1 วันทำการ ถ้าคุณต้องการการดูแลระดับ 24/7 จริง ๆ ควรใช้ทีม managed service ที่มีคนผลัดเวร

จ่ายเงินยังไง มีใบเสร็จไหม

โอนผ่านธนาคาร งานรายชั่วโมงและตรวจระบบเก็บหลังจบงาน ส่วน retainer เก็บต้นเดือน ออกใบเสร็จ/ใบแจ้งหนี้ให้ได้ตามที่ฝ่ายบัญชีต้องการ
